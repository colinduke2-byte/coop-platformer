# DREAMERS — Visual Overhaul Plan ("gorgeous, like Rayman Legends")

Colin's decisions (asked 2026-10-08):
- **Art method:** keep drawing shapes in code, plus **painterly textures baked by scripts**
  (PNG files generated by `tools/art/*.py`, all original, regenerable). No hand-drawn files.
- **Performance:** **quality presets** (High / Medium / Low), picked automatically, changeable in Settings.
- **Scope:** characters, worlds & terrain, enemies & bosses, UI / menus / maps — everything.
- **Style:** **same designs, much richer.** Keep every character, enemy, level and silhouette;
  repaint them with texture, light and depth. No redesigns, no gameplay changes.

Rule for the whole overhaul: **visuals only.** Collision shapes, sizes, timings, level
layouts and tuning do not change. `bash tools/check.sh` must stay green after every step
(457 tests today) and the level audit must stay at 0 issues.

---

## What makes Rayman Legends look the way it does (the checklist we judge against)
1. **Painted surfaces** — brush texture, soft colour variation, darker toward edges/depth; never a flat fill.
2. **Depth** — 6–8 parallax layers, atmospheric mist between them, dark blurred foreground
   foliage framing the screen edges.
3. **Light** — a warm key light, rim light on characters, god rays, bloom on glowing things,
   strong per-world colour grading.
4. **Delicate ink** — a thin, tapering, slightly irregular dark line; never one thick uniform stroke.
5. **Life** — things sway, breathe, sparkle, flutter, react to the players.

The game already has the shapes and much of (5). This plan adds (1)–(4).

## Phase 0 — Foundation (do first)

### 0.1 Texture baker
- New `tools/art/bake_textures.py` (Python + PIL + numpy if available; pure PIL fallback).
  Generates **tileable** 256×256 (or 512×512 for big surfaces) PNGs into `art/textures/`:
  `ground_<style>.png` (earth, rock, snow, sand, brick, metal, coral, crystal, nebula),
  `lip_<style>.png` (grass, snow, moss, sand, brass, coral), `bark.png`, `cloth.png`,
  `fur.png`, `shell.png`, `jelly.png`, `paper.png`, `brush_mask.png`.
- Technique: layered value noise + directional brush-stroke stamps (elongated soft ellipses at
  a dominant angle), then **greyscale** output. Colour comes from the LevelTheme at draw time
  (texture multiplies/overlays the theme colour) so 35 themes don't need 35 texture sets.
- Seamless tiling: generate on a torus (wrap noise coordinates) and verify by tiling 2×2 in a
  check image.
- `art/textures/README.md`: "generated — run `python3 tools/art/bake_textures.py`".
- Update CLAUDE.md golden rule 8: "Art is procedural: shapes in code, textures baked by
  scripts in tools/art. No hand-drawn image files."

### 0.2 Quality presets
- Extend `core/settings.gd` with `graphics: int` (0 Low, 1 Medium, 2 High) saved with the other
  settings; add a row to the Settings menu (pause → Settings).
- First launch auto-pick: web (`OS.has_feature("web")`) on a mobile UA or small screen → Low,
  other web → Medium, desktop → High.
- A static helper `Gfx.at_least(level)` (new `core/gfx.gd`, class_name `Gfx`, not an autoload)
  that every new effect checks. Tests run headless → treat as Medium so code paths are covered
  but nothing heavy runs.

### 0.3 Before/after harness
- New `tools/art/compare.sh <tag>`: screenshots a fixed list of ~24 spots (2 per world, bonus
  levels, title, character select, each world map, results, Lum Shop, enemy gallery) into
  `$SCRATCH/compare/<tag>/` and stitches a side-by-side contact sheet against `baseline/`.
  Build on the existing `tools/shots.sh`, `tools/scene_shot.tscn` (`--scene=`, `--map_world=`,
  `--wait=`, `--out=`) and `tools/enemy_gallery.tscn -- --shots=DIR`.
- Take the **baseline** before changing any art.
- Performance gate each phase: `godot --path . res://tools/bench.tscn -- --drawcalls` on 3
  heavy levels; targets: High 120 fps on desktop, Low 60 fps in the web build. Static art must
  stay baked through `MeshPainter` (one draw call per piece); textured fills mean MeshPainter
  needs UVs (see 1.1).

Deliverable: baseline gallery + texture sheet sent to Colin.

## Phase 1 — Worlds & terrain (biggest win)

### 1.1 Painted terrain and blocks (`world/terrain.gd`, `world/block.gd`, `world/mesh_painter.gd`)
- Give `MeshPainter` UV support (world-space UVs = position / texture scale) and a per-mesh
  texture + material, so a baked terrain is still one draw call.
- New canvas shader `world/shaders/painted_ground.gdshader`:
  theme colour × texture, **depth darkening** (darker the further below the lip, using a
  distance-from-top value baked into vertex colour or UV2), subtle hue variation from a
  low-frequency noise, soft ambient-occlusion band under the lip.
- Lip (`_draw_lip`): textured grass/snow/sand band with **overhanging tufts/blades** drawn as
  small baked polygons sticking up/over the edge (density by preset).
- **Ink line:** replace the uniform `draw_polyline(..., OUTLINE_W)` with a tapered, slightly
  wobbly line (vary width 1.5–4 px along the run, darker at bottom-left = shadow side).
- Same treatment for `Block`, ledges, moving platforms, crumbles, beat blocks (keep their
  colour coding readable!).
- Each LevelTheme gets `ground_texture`, `lip_texture` (StringName keys into the baker set)
  and `texture_scale`. Fill in all 35 themes in `world/themes/*.tres`.

### 1.2 Deeper backdrops (`world/backdrop.gd`, 1187 lines)
- Every `Scenery` (`hills, forest, cave, canopy, river, castle, candy, ice, jungle, ruins,
  factory, ocean, deep, nebula`) goes to 6–8 layers: far sky → distant silhouettes → haze band
  → mid shapes → haze band → near shapes → (High) extra near layer.
- **Atmospheric perspective:** `_haze()` already exists; add soft horizontal mist bands
  (gradient quads) between layers, coloured from `sky_bottom`.
- Painted fills: backdrop meshes use the same painted shader with a soft brush texture at low
  contrast.
- Sky: richer gradient (3–4 stops), sun/moon glow halo, cloud banks with soft undersides.
- Keep the new `_critters()` flocks / parrots / gulls / smoke / shooting stars.

### 1.3 Foreground framing
- New `world/foreground.gd` (added automatically by `level.gd` from the theme's world style):
  dark, slightly blurred silhouettes (leaves, vines, pipes, coral, icicles, crystals) in a
  Parallax2D with scroll scale > 1, only near the top/bottom screen edges so they never cover
  the playfield. High: 2 layers; Medium: 1; Low: none.

### 1.4 Light & colour
- Per-world colour grade: a screen-space shader on a top CanvasLayer (or WorldEnvironment
  where supported) with lift/gamma/gain + saturation + vignette, parameters on LevelTheme
  (`grade_*`). Defaults per world: warm meadow, cool frost, humid jungle, brassy factory,
  deep-blue sea, violet nebula.
- **Bloom/glow** (High/Medium): on Lums, gems, GlowLights, lava, zaps, the goal portal.
  Desktop: `WorldEnvironment` glow; web (Compatibility renderer): a cheap additive halo sprite
  per glowing thing instead.
- **God rays:** upgrade `Backdrop.light_shafts` (soft additive quads that slowly sway), enable
  for forest/canopy/jungle/ruins/ocean levels.
- Dark levels (ambience `darkness`): lights already exist (GlowLight, dreamer lights); add
  light-occluder-free "light pools" so terrain near lights brightens.

### 1.5 Living decor (`decor/deco.gd`)
- Painted shading on all deco kinds (texture + rim highlight + tapered ink).
- Grass/flowers **bend away from players** passing through (cheap: per-deco skew driven by
  nearest player distance, only for on-screen deco via `View.sees`).
- Water (`world/water.gd`): surface highlight band, moving caustic texture in the body,
  (High) a faint reflection of the sky colour.
- Waterfalls: foam at the bottom, mist puffs.

Deliverable: before/after gallery of every world + bench numbers.

## Phase 2 — Characters (`characters/character_rig.gd`, 849 lines; CharacterDef .tres)

- **Painted shading** on every rig part: cloth/skin texture (from baker), a soft shadow side
  (gradient away from the key light), **rim light** on the light side using the theme's
  `sun` colour, tapered ink line.
- Faces: eye highlights, softer pupils, more expressions driven by state —
  determined (sprint), scared (falling far / hurt), cheering (victory), dizzy (bubble), sleepy
  (long idle). Keep the big goofy noses.
- Animation polish (no gameplay change — rig only):
  smoother run cycle (arms swing opposite legs, head bob), **follow-through** on hats, plumes,
  scarves, hair, bandana tails (spring-damped offsets), stronger squash & stretch on jump /
  land / punch with anticipation frames, skid/brake pose, long-idle yawn + stretch, two or
  three victory dances picked at random.
- Shop outfits and hats (`characters/wardrobe.gd`) use the same cloth texture tinted by the
  outfit colours. Check every outfit with `tools/outfit_gallery.gd`.

Deliverable: character + outfit gallery, a short clip if possible (`tools/clip.sh`).

## Phase 3 — Enemies & bosses (`enemies/*.gd`, 28 enemies + 6 bosses)

- Shared look in `enemies/enemy.gd`: painted shading, rim light, tapered ink, material
  textures per enemy (`fur`, `shell`, `metal`, `jelly`, `bark`, …) via a small helper that
  `_draw_body` implementations call. Keep each enemy's palette and silhouette.
- **Readability rule:** enemies and hazards must stay the highest-contrast things on screen —
  slightly brighter saturation and a stronger ink line than terrain; warning tells (glows,
  crackles, shadows) get bloom.
- Bosses (King Grumblo, Baron Bristleback, Grumblefrost, Chamelia, Cuckoolossus, Inkabella):
  intro moment (camera nudge + painted name card), hit flash + shockwave ring, phase-change
  flourish, big defeat burst with confetti and fireworks (Vfx already has `firework()`).
- Verify with `tools/enemy_gallery.tscn -- --shots=DIR` against the baseline.

## Phase 4 — UI, menus & maps

- **Storybook UI kit** in `ui/ui_style.gd`: paper/parchment panels (baked `paper.png`),
  torn/deckled edges, a friendly rounded display font from Google Fonts (OFL licence, bundle
  the .ttf in `ui/fonts/`), wiggle/pop animations on selection.
- Title (`ui/title.gd`): painted scene, slow camera drift, logo bounce + sparkle.
- Character select: dreamers on little stages with spotlights; outfit swap with a puff.
- World maps (`ui/world_map.gd`, one `_bake_wN()` per world): painted textures on the landscape
  meshes, a paper-map border, drifting cloud shadows, critters for every world (W5 has fish,
  gulls and Inkabella's eyes already), animated badges.
- HUD (`ui/hud.gd`): chunkier Lum counter with pop, painted gem slots, polished boss bar.
- Results (`ui/results.gd`): painted panel, medal/stars, count-up numbers, confetti finish.
- Pause menu and Lum Shop (`ui/lum_shop.gd`) restyled with the kit.

## How to work (notes for whoever executes this)
- Do one phase at a time; after each: check → commit → deploy → before/after gallery to Colin.
  He can redirect between phases.
- Commit messages end with the two attribution lines from the session reminder; no model names.
- Useful commands:
  - Full check (long, ~45 min): run detached and wait for `EXIT` in the log.
  - Subset tests: `godot --headless --path . res://tests/test_runner.tscn -- only=<substr>`.
    A parse error in `tests/run_tests.gd` makes the runner hang — capture output with `timeout`.
  - Level screenshots: `bash tools/shots.sh DIR -- --level=res://levels/X.tscn --at="x,y;..." --zoom=0.45`.
  - Menus/maps: `xvfb-run -a -s "-screen 0 1920x1080x24" godot --rendering-driver opengl3 --path . res://tools/scene_shot.tscn -- --scene=res://ui/world_map.tscn --map_world=w5 --wait=1.5 --out=FILE`.
  - Shaders must work in the **Compatibility** renderer (the web export) — test with
    `--rendering-driver opengl3`.
- Static art stays baked (MeshPainter, one draw call); animated `_draw()` uses
  `View.redraw(self)`, never plain `queue_redraw()` every frame.
- Deploy: Windows export → zip → `bash tools/web/deploy_pages.sh` → split pieces →
  republish the play artifact (https://claude.ai/artifact/ADX5rr3V6dWD2ooZ3emthA, root
  `build/web`, files `index.js`, `pieces/parts.json`, every `pieces/part*.webm`) → verify the
  last piece's md5 on Pages with curl. The Windows zip (~47 MB) is too big to attach; share the
  Pages link `https://colinduke2-byte.github.io/coop-platformer/Dreamers-Windows.zip`.
